# Sources, currency, and learning AWS independently

[Guide index](README.md)

**Research snapshot: 2026-10-04.** The linked official pages are reference points, not a promise that every Region, account, CLI version, and IaC provider supports every feature. No AWS account is needed to read this guide, and the examples have not been deployed as part of this learning path. Recheck these findings before deployment; AWS primary sources are the research base.

## CI identity currency: GitHub OIDC

GitHub’s default OIDC subject now includes immutable owner/repository IDs for new repositories and qualifying renames/transfers from July 15, 2026. Older repositories may retain name-only subjects unless opted in. The environment/branch portion still matters. Match the exact configured subject rather than assuming every tutorial’s `repo:ORG/REPO:...` form works. This is a GitHub identity-provider change affecting AWS trust, not an AWS IAM deprecation. [GitHub rollout](https://github.blog/changelog/2026-04-23-immutable-subject-claims-for-github-actions-oidc-tokens/), [GitHub AWS federation guide](https://docs.github.com/en/actions/how-tos/secure-your-work/security-harden-deployments/oidc-in-aws).

## IAM: the simplified formula has exceptions

**Current AWS policy behavior:** begin with implicit deny; an applicable explicit deny wins. Identity policies grant permissions; boundaries and organization controls constrain them rather than grant access. Same-account resource policies can grant access independently of identity-policy allows. Cross-account authorization normally requires permission on both sides. But the principal named in a resource policy matters: a grant to a role ARN differs from a grant directly to an assumed-role session ARN. Direct same-account session grants can bypass some **implicit** denies in identity/session/boundary policies; explicit denies still matter. KMS and role trust have additional rules. Therefore “all policy allows must intersect” is an educational shortcut, not the full evaluator. Read [evaluation logic](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html) and [enforcement details](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic_policy-eval-denyallow.html) before designing delegation or diagnosing a surprising authorization result.

## Choose the document that answers the question

| Document                                         | Use it for                                                                                           | What it does not establish alone                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| User guide                                       | Service mental model, configuration, constraints, operating procedures                               | Exact SDK request types                                          |
| Developer guide                                  | Application integration, credentials, examples, lifecycle                                            | That an example meets your production requirements               |
| API / CLI reference                              | Required fields, response shapes, errors, pagination, idempotency parameters                         | Architecture suitability; remember local CLI versions can lag    |
| Security guide / service authorization reference | IAM actions, resource ARN support, condition keys, encryption and trust                              | Network connectivity                                             |
| Well-Architected Framework                       | Questions and trade-offs across reliability, security, operations, performance, cost, sustainability | A mandatory one-size architecture                                |
| Prescriptive Guidance / architecture center      | Implementation patterns with explicit assumptions                                                    | Universal advice independent of workload                         |
| Quotas                                           | Regional/account/resource limits and increase procedures                                             | Your account's actual approved quota or instantaneous capacity   |
| Pricing                                          | Billing units, minimums, transfer charges, Region differences                                        | Your total bill without a workload model                         |
| FAQ                                              | Fast orientation and common constraints                                                              | Most precise source when it conflicts with service docs          |
| What's New                                       | Launch date, announced Regions, general availability vs preview                                      | Full operational limitations                                     |
| Official blog                                    | Worked examples and motivation                                                                       | A guarantee that old commands, defaults, or costs remain current |

For an unfamiliar service, answer: **what is the resource; which account/Region owns it; who calls which APIs; what runs in the data plane; which identities and network paths are involved; what scales/fails; what is billed; how do I observe and delete it?** Then read its security, quota, and pricing sections before copying a tutorial.

## Repeatable currency check

1. Open the owning service's current HTML guide, not only a search snippet or cached PDF. Find prerequisites, limitations, supported Regions, engine/runtime versions, and lifecycle notices.
2. Cross-check major changes against What's New or a lifecycle page. Distinguish announcement date, effective date, preview, GA, and existing-customer exceptions.
3. Check API/CLI and the **pinned** IaC provider's schema. A launched AWS feature may not yet be supported by your installed tools.
4. Inspect account quotas, organization restrictions, and Region availability with read-only calls. Documentation cannot tell you your account's effective state.
5. Model costs using your Region, hours, AZs, requests, bytes, retention, and support tier. Include quiet-hours infrastructure costs.
6. Record source URL, retrieval date, decision, assumptions, and any conflicting source. If sources conflict, prefer the current owning-service lifecycle guidance; document unresolved uncertainty and avoid relying on the disputed detail.
7. Validate a minimal change in a sandbox, review the IaC plan/change set, and test rollback. Recheck before production adoption and quarterly thereafter.

## Primary reference shelf

- Architecture review: [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html), [AWS Prescriptive Guidance](https://aws.amazon.com/prescriptive-guidance/).
- Identity: [IAM security best practices](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html), [IAM service authorization reference](https://docs.aws.amazon.com/service-authorization/latest/reference/reference_policies_actions-resources-contextkeys.html).
- Networking: [VPC user guide](https://docs.aws.amazon.com/vpc/latest/userguide/what-is-amazon-vpc.html), [VPC pricing](https://aws.amazon.com/vpc/pricing/).
- Containers: [ECS developer guide](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/Welcome.html), [ECS best practices](https://docs.aws.amazon.com/AmazonECS/latest/bestpracticesguide/intro.html).
- Data: [RDS user guide](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/Welcome.html), [S3 user guide](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html), [DynamoDB developer guide](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/Introduction.html).
- Operations: [CloudWatch user guide](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/WhatIsCloudWatch.html), [AWS Health](https://health.aws.amazon.com/health/status), [AWS CLI reference](https://docs.aws.amazon.com/cli/latest/reference/).
- Change detection and cost: [What's New](https://aws.amazon.com/new/), [Service Quotas](https://docs.aws.amazon.com/servicequotas/latest/userguide/intro.html), [Pricing Calculator](https://calculator.aws/), [service pricing](https://aws.amazon.com/pricing/).

Use these as entry points, then cite the exact subsection supporting a design decision. A homepage link is useful for navigation, but weak evidence for a specific operational claim.
