# IAM threat workbook

Continue from [guide chapter 28](GUIDE.md#28-threat-modeling-and-controlled-experiments). Scope: generated local fixtures; an attacker may control requests, an ordinary account, an untrusted browser origin or a specifically identified credential. Operators/IdPs/issuers are trusted only where stated. A malicious issuer invalidates the issuer trust assumption; a signature cannot repair it.

Each row contains all eight dimensions. The ordered arrows are attack steps. Detection is a hypothesis for monitoring, not a guarantee. Residual risk names the surviving capability after the listed control. Reproduce only the linked local labs; the other rows are threat-analysis exercises.

| Threat | Attacker capability / violated assumption | Preconditions | Ordered attack / impact | Prevention | Detection | Residual risk |
| --- | --- | --- | --- | --- | --- | --- |
| Credential stuffing | known leaked pairs / credential uniqueness | reused passwords, permissive login | load pairs → try logins → take account | breached-password screening, passkeys/MFA, layered throttles | failures followed by success across networks | recovery hijack and authorized-device compromise |
| Brute force | many guesses / bounded online attempts | weak credential, no attempt bound | enumerate guesses → find verifier match → impersonate | strong enrollment policy, per-account/client/network limits | failure-rate and hashing-load alarms | low-rate distributed guesses; DoS from limits |
| Password spraying | small guess set across users / account-only limits | common passwords, exposed identifiers | pick one password → try many accounts → repeat slowly | weak-password rejection, cross-account signals, MFA | correlated password-spray patterns without logging guesses | distributed slow campaigns |
| Phishing | counterfeit UI / origin-authenticator binding | phishable credential, persuaded user | lure → capture password/OTP → real-time relay → login | RP-bound WebAuthn, verified recovery, user education | anomalous auth context and reported lures | malware on genuine origin/device |
| Session fixation | choose known pre-login ID / fresh post-login context | app reuses caller-controlled ID | plant ID → victim logs in → reuse ID → act as victim | rotate ID at auth/privilege change; stage 03 | unexpected ID continuity or parallel sessions | stolen new ID remains usable |
| Session hijacking | steal current cookie / secret confidentiality | XSS-readable cookie, insecure hop/device | extract ID → replay → access | Secure/HttpOnly, TLS, short bounds, revoke state | unusual session activity; device-context changes | XSS can still act through victim browser |
| XSS | script execution at app origin / trusted client code | unsafe output/dependency | inject → read storage or invoke API → exfiltrate/change data | contextual encoding, sanitization, CSP, dependency review | CSP reports, suspicious script/network behavior | valid same-origin actions under compromise |
| CSRF | foreign page causes requests / user-intent binding | ambient cookie, unprotected mutation | host form → victim browser attaches cookie → mutate | bound CSRF proof, Origin check, SameSite; stage 04 | rejected origins/proofs | same-origin XSS; unsafe GET |
| Token theft | copy bearer secret / presentation confidentiality | logs/storage/proxy leak | extract token → present before expiry → steal data | TLS, redaction, scope/lifetime, sender constraints | unusual audience/location and credential use | attacker holding proof key or controlled client |
| Token replay | repeat accepted bytes / freshness | bearer credential or missing nonce state | capture → resend → repeat action | stateful one-use handling where needed; DPoP/mTLS appropriately | duplicate IDs/nonces, repeated side effects | bearer replay remains intentional until revoked |
| Code interception | observe redirect code / redemption binding | insecure native handler, missing PKCE | intercept code → token exchange → access | S256, exact redirects, one-use code; stages 09–10 | invalid verifier/binding attempts | verifier theft, compromised initiating client |
| Redirect URI manipulation | choose callback / registered recipient binding | prefix/wildcard checks | submit lookalike → user approves → receive code | exact match; native loopback exception only | invalid redirect metrics/config changes | compromised correctly registered callback |
| Login CSRF | initiate attacker login / browser-account binding | callback not transaction-bound | attacker signs in → inject callback into victim → victim acts in attacker account | browser-bound state/nonce/PKCE, login Origin policy | missing/mismatched transaction state | malicious code in victim origin |
| OAuth CSRF | inject authorization response / initiating-user binding | predictable or absent correlation | create flow → inject response → wrong grant/account association | fresh browser-bound transaction correlation | callback state failures | stolen transaction state in compromised browser |
| Open redirect | arbitrary navigation destination / credential delivery confinement | app/AS forwards URL input | enter redirect URL → append credential flow → leak to attacker | allowlisted destinations, no open redirect endpoints | unusual redirect hosts | allowed endpoint compromised |
| PKCE downgrade | remove/change challenge / required redemption proof | optional PKCE or plain fallback | strip challenge → receive code → redeem without verifier | require S256 on configured clients; fail missing fields | missing/unsupported challenge method | verifier compromised through XSS |
| OAuth mix-up | control one AS / response issuer attribution | client supports multiple AS, ambiguous callback | malicious AS mixes honest code → wrong token endpoint → credential leak | expected issuer/response iss or distinct callback binding | issuer/endpoint mismatches | trusted AS compromise |
| Confused deputy | call privileged service / actor-target authority binding | service accepts arbitrary target/user header | low-priv caller requests high-priv action → deputy acts → leak | authenticate caller and scoped delegation; target policy | actor/subject/target mismatch events | deputy’s own key compromise |
| Refresh theft | copy RT / long-lived grant confidentiality | exposed client storage/secret | steal → refresh repeatedly → persistent access | secure storage, rotation/sender constraint, absolute expiry | reuse-family events; changed client context | thief suppresses legitimate refresh, avoiding reuse detection |
| JWT algorithm confusion | choose JOSE header / verifier-selected algorithm | mixed key/algorithm acceptance | change alg → forge under alternate interpretation → privilege | fixed algorithm/key-type/profile; stage 07 | unexpected-alg failures | correct signing key stolen |
| Wrong audience | obtain valid token for another API / recipient binding | signature-only validator | obtain low-risk token → present to high-risk API → access | exact intended API audience; stage 07 | audience failures; multi-API misuse | malicious issuer lies about audience |
| Wrong issuer | mint token under attacker key / configured issuer trust | dynamic issuer/key URL trusted from token | mint → offer attacker JWKS → accepted subject | pinned issuer/discovery/key source; stage 07 | unexpected issuer/SSRF attempts | trusted issuer compromised |
| ID-token substitution | own valid ID token / artifact-use separation | API accepts RP ID-token audience/type | sign in to client → present ID token to API → unwanted access | distinct access-token profile/audience/type; stage 07 | wrong-profile/audience rejections | issuer/profile misconfiguration |
| SAML replay | captured assertion / one-use federation transaction | no request/replay cache | capture form → POST again → create fresh session | InResponseTo, browser binding, assertion replay cache; stage 18 | repeated IDs/request references | IdP issues new valid assertion |
| XML signature wrapping | crafted XML / consume signed content | verifier and app select different nodes | wrap signed assertion → add unsigned privileged node → app reads it | maintained library, consume verified node, parser hardening | signature/duplicate-structure failures | parser/library vulnerability |
| SCIM over-provisioning | connector/group input / bounded mapping | arbitrary group maps admin/owner | create/rename group → sync elevated role → privilege | tenant-bound connector, explicit allowed mapping, protect owners | unexpected privileged group/role changes | authorized connector compromised |
| SCIM offboarding failure | stale provisioning channel / bounded revocation | retry queue stuck, sessions outlive local status | directory deactivates → delivery fails → user continues | current membership check, retries/reconciliation, revocation SLA | oldest pending event, divergence checks | outage beyond SLA; offline token paths |
| Cross-tenant access | valid user and arbitrary ID / tenant isolation | ID-only query or untrusted tenant claim | log in A → request B ID → receive B data | stored tenant binding, live membership, composite keys; stage 17 | tenant mismatch denials and access review | alternate unchecked export/search path |
| Privilege escalation | edit assignments / assignment authority | self-service role field, weak admin check | set own role → invoke privileged endpoint | separate assignment policy, owner transfer transaction | privilege-change audit/alerts | compromised authorized owner |
| IDOR | enumerate/guess object IDs / object authorization | authenticated route lacks ownership check | request other ID → read/update object | per-resource policy; identifiers not access controls | object denial patterns | resources intentionally shared too broadly |
| Excessive permissions | use legitimately broad role / least privilege | wildcard grant, inherited role accumulation | gain ordinary account → exercise unrelated grant → impact | narrow roles/scopes, review, expiry, SoD | actual-use versus granted-rights review | needed privileged access can be abused |
| Compromised IdP | issue valid assertions / issuer integrity | stolen issuer key or malicious admin | mint trusted login → enter app → use mapped permissions | restricted tenant mapping, independent high-risk controls, emergency distrust | unusual subjects/assurance/config changes | issuer controls authentication; fail-closed blocks legitimate users too |
| Signing-key compromise | sign arbitrary token / private-key secrecy | exported/leaked key | mint admin/audience token → pass crypto → attack | KMS/HSM, short life, emergency key distrust + live policy | key access alerts, unexpected issuance patterns | offline verifiers with stale key caches |
| Client-secret leakage | authenticate client / confidential boundary | secret in repository/image/log | extract → request token → service authority | secret manager, asymmetric auth, rotation, tight scopes | anomalous client issuance/source | legitimately compromised client process |
| Unsafe logging | read logs / credential confidentiality | middleware logs headers/body | retrieve bearer/RT/password → reuse → impersonate | allowlist/redact fields; stage 21 | secret scanning on test/authorized logs | past leaks and overprivileged log readers |
| Insecure logout | retain captured credential / revoked continuity | cookie cleared but server row remains | victim logs out → attacker replays old ID → access | invalidate server state; distinguish IdP/app/RT logout | use after logout/revoke event | separately valid API tokens and OP session |
| Account linking | control matching address/claim / identity ownership | email-only automatic merge | create external identity → match victim email → gain account | proof of both identities, exact trusted issuer/sub | unexpected link/provider changes | weak recovery or already compromised identity |
| MFA bypass | exploit weaker alternative / equivalent assurance | recovery/API ignores step-up | skip MFA route → call privileged API → succeed | enforce assurance at operation, protect recovery, freshness | privileged action without required auth context | stolen already-stepped-up session |
| Supply chain | modify dependency/build / trusted implementation | unreviewed update/package compromise | install malicious library → extract secrets/alter validator → access | pinned lock, review, provenance, minimal privileges, advisories | dependency changes, unexpected network/file behavior | undiscovered upstream compromise |

## Work one threat through completely

Hypothesis: signature validity alone cannot enforce tenant isolation. Setup: stage 17’s Alice/A fixtures; control: unchanged valid principal; independent variable: document tenant. Driver: `npm test` or the browser’s tenant/document selectors. Prediction: A succeeds, B fails even though Alice remains authenticated. Actual result belongs in [the experiment ledger](experiments/README.md); do not write a claimed production guarantee here. Next experiment: add an export worker and prove its policy cannot be bypassed by changing the queued resource ID.
