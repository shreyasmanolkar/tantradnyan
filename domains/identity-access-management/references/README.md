## Versions and implementation reading

NIST’s fourth revision is published; the guide does not use obsolete 800-63-3 assumptions as current requirements. OIDC Core incorporates errata 2. OAuth’s baseline here is OAuth 2.0 plus RFC 9700 BCP and applicable extensions; do not mistake a draft’s name for a final security baseline. SCIM remains grounded in 7643/7644, with cursor pagination a separate extension. Check WebAuthn’s status banner and browser/library support before adopting Level 3-specific features. New extensions do not silently become supported by the teaching service.

The [lockfile](../iam-first-principles/package-lock.json) pins actual installed package versions. Maintainer documentation: [jose](https://github.com/panva/jose), [openid-client](https://github.com/panva/openid-client), [oidc-provider](https://github.com/panva/node-oidc-provider), [node-saml](https://github.com/node-saml/node-saml). Use installed source at the locked version to follow a validator; pin an upstream commit if recording implementation-specific findings. The local provider advertises development-only interactions, adapter and signing keys; passing tests does not make those production settings acceptable.

Research uncertainty is explicit: current interoperability and vendor defaults must be checked for the provider/tenant at deployment time. No commercial product’s private architecture or offboarding latency is asserted from the transcript material.
